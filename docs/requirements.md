# 要件定義書

## 1. 概要

### 1.1 プロジェクト名
Ledge

### 1.2 背景
Windows向けクリップボードマネージャー「Edge Drop」（edgedrop.app）、およびMac向けシェルフアプリ「Yoink」「Dockside」を参考に、両OSに対応した無料・オープンソースのファイル/クリップボード一時置き場アプリを自作する。既存アプリは各OS単体対応かつ有料のものが多く、無料でWindows/Mac両対応の選択肢が乏しいことが動機。

### 1.3 目的
- ドラッグ&ドロップ操作を快適にする画面端常駐の「一時置き場（シェルフ）」を提供する
- クリップボード履歴の記録・ピン留め・検索を提供する
- Windows / macOS の両方で同一の操作感を実現する

### 1.4 対象ユーザー
開発者本人（shiki）の個人利用を第一とする。将来的なOSS公開は視野に入れるが、要件定義段階では個人ユースケースを優先する。

---

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| シェルフ (Shelf) | 画面端に表示される、ファイル/フォルダ/テキストの一時置き場ウィンドウ |
| ピン留め | クリップボード履歴やシェルフ内アイテムを自動削除対象から除外する操作 |
| スタック | 複数のクリップボードアイテムを1つにまとめる操作 |
| ドロップターゲット | OSのドラッグ&ドロップ操作を受け付けるウィンドウ/領域 |

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 対応OS | Windows 10/11、macOS（Apple Silicon優先、Intel対応は可能な範囲） |
| パフォーマンス | 常駐時のメモリ使用量を抑える（Electron比で軽量なランタイムを採用） |
| 起動速度 | シェルフ呼び出しからウィンドウ表示までの体感遅延を最小化する |
| データ永続化 | アプリ再起動後もシェルフ内容/クリップボード履歴を保持する |
| プライバシー | クリップボード履歴はローカル保存を基本とし、外部送信は行わない（F-22実装時を除く） |
| ライセンス | 無料・可能であればOSS化を前提とする |

## 6. 画面要件（概要）

- **シェルフウィンドウ**: 画面端常駐、半透明、ドラッグ&ドロップ対応領域
- **クリップボード履歴パネル**: 一覧表示、検索バー、ピン留めアイコン
- **設定画面**: ホットキー設定、表示位置/透明度、自動クリア期間、自動起動ON/OFF
- **システムトレイ/メニューバーアイコン**: 左クリックでシェルフ表示切り替え、右クリックで設定/終了メニュー

## 8. 制約事項・リスク

- macOSにおけるグローバルなドラッグ開始検知（F-08）は、Accessibility APIまたはprivate APIへの依存が想定され、実装難度・審査（Mac App Store配布時）への影響が高い。App Store外配布（notarization経由の直接配布）を前提とする
- クリップボード監視はmacOS側でプッシュ通知APIが存在しないため、ポーリング方式（数百ms間隔）を採用する。バッテリー消費への影響を検証する必要がある
- Windowsのセキュリティソフトによっては、クリップボード監視やグローバルフックが誤検知される可能性があるため、コード署名を検討する

## 9. Out of Scope（本要件定義の対象外）

- クラウド経由の複数ユーザー間ファイル共有（Edge Drop本家の「自分宛メモ」的機能を超えた共同編集等）
- モバイル（iOS/Android）対応
- Linux対応（将来検討の余地はあるが本要件定義では扱わない。ただし開発時のコンパイル検証目的でLinux上でも`cargo check`が通る構成は維持する。詳細は`architecture.md`参照）

## 10. データモデル詳細

実装着手にあたり、3章・5章の内容を具体的なテーブル/フィールドレベルまで落とし込む。DDLは`architecture.md`に記載し、本章では意味論・運用ルールを定義する。

### 10.1 シェルフアイテム（shelf_items）

- **参照方式の帰結**: F-02は「実体コピーは行わない」ため、シェルフはあくまで元ファイルへのパス参照を保持する。よって以下の状態遷移が発生しうる：
  - 元ファイルが**移動/リネーム**された場合 → パス不一致で検出不能（OSのファイルシステム監視までは行わない。将来的な拡張候補とし、Phase1〜4では対象外）
  - 元ファイルが**削除**された場合 → シェルフ表示時にパス存在チェックを行い、存在しなければ「missing」状態としてグレーアウト表示し、警告アイコンを出す。再ドロップ操作は無効化し、削除のみ可能とする
  - 元ファイルが**外部メディア（USB等）上**にあり、メディアが取り外された場合 → 同様にmissing扱い（一時的な不在の可能性があるため、アイテム自体は削除しない）
- **フォルダのドロップ**: フォルダは中身を展開せず、フォルダパス自体を1アイテムとして保持する（参照のみの原則に合わせる）
- **重複ドロップ**: 同一パスの再ドロップは許可し、別アイテムとして追加する（ユーザーが意図的に複数回参照したい場合を妨げない）
- **並び順**: `sort_order`（追加順、ドラッグでの手動並び替えは将来検討／Phase1では追加日時降順固定）
- **ロック（F-06, Phase3）**: `locked`フラグを持ち、「全消去」操作の対象から除外する。個別削除は可能

### 10.2 クリップボード履歴（clipboard_history, Phase2〜）

- **重複排除方針**: 同一内容（テキストは正規化した内容のハッシュ、画像はバイト列ハッシュ）が既存履歴に存在する場合、新規レコードは作らず**既存レコードのタイムスタンプを更新して先頭に繰り上げる**（ピン留め状態・タグは保持）。これにより同じ文言を繰り返しコピーしても履歴が埋まらない
- **自己ループ防止**: F-12（履歴からの貼り付け）でアプリ自身がクリップボードに書き込んだ内容は、直後の監視イベントで「新規コピー」として再記録しない。実装は「自己書き込み時にcontent hashを一時保持し、直後の変更検知はそのhashと一致すればスキップ」する
- **画像の保存**: 画像はDBにBLOB格納せず、アプリデータディレクトリ配下のキャッシュフォルダにPNGファイルとして保存し、DBにはファイルパスとサムネイルパスのみ記録する（DB肥大化・SQLiteのパフォーマンス劣化を避けるため）
- **ファイルパスのコピー**: OSのファイルコピー操作（Explorer/Finderで「コピー」した場合）もクリップボード経由で検知可能な範囲は履歴化する。内容種別は`file_paths`として、シェルフのmissing判定と同様のルールを適用する
- **自動クリア（F-16）**: 「件数上限」または「経過日数」のいずれかを超えたら削除。ピン留めアイテムは対象外。画像キャッシュも同時に削除する。デフォルト値は「500件 または 30日」を暫定初期値とする（設定画面で変更可能）

### 10.3 プライバシー・除外規約

- Windows/macOSには、パスワードマネージャー等が「この内容を履歴管理ソフトに記録させない」ことを示す非公式の共通規約が存在する：
  - Windows: クリップボードフォーマット `ExcludeClipboardContentFromMonitorProcessing` が同時にセットされている場合、監視対象から除外する
  - macOS: NSPasteboardの型として `org.nspasteboard.ConcealedType` / `org.nspasteboard.TransientType` / `org.nspasteboard.AutoGeneratedType` のいずれかが付与されている場合、監視対象から除外する（Paste, Alfred等の主要クリップボードマネージャーが準拠している事実上の標準）
  - この除外規約への準拠をF-11の実装要件に追加する（非機能要件というよりF-11のサブ要件として明記）

### 10.4 設定の永続化

- ホットキー・表示位置/透明度・自動クリア期間・自動起動ON/OFF等の**アプリ設定**はSQLiteではなく、アプリデータディレクトリ配下の`settings.json`で管理する（`tauri-plugin-store`を利用）。SQLiteは「データ」（履歴・タグ・ピン）、JSONストアは「設定」という役割分担にする

## 11. エラーハンドリング・ロギング方針

- Rust側のドメインエラーは`thiserror`で型付けし、Tauriコマンドの戻り値はフロントで扱いやすいよう`Result<T, ShelfError>`をシリアライズして返す（`ShelfError`はコード＋ユーザー向けメッセージを持つ構造体）
- フロントエンドはコマンド呼び出し失敗時にトースト通知を表示し、致命的でない限りアプリを継続動作させる
- ログは`tracing` + `tracing-appender`でアプリログディレクトリにローテーション出力する。**クリップボードの内容そのものはログに出力しない**（プライバシー要件との整合）。記録するのはイベント種別・エラー内容・スタック程度に留める
