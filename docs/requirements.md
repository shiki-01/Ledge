# 要件定義書

## 1. 概要

### 1.1 プロジェクト名（仮）
Shelf Drop（仮称）

### 1.2 背景
Windows向けクリップボードマネージャー「Edge Drop」（edgedrop.app）、およびMac向けシェルフアプリ「Yoink」「Dockside」を参考に、両OSに対応した無料・オープンソースのファイル/クリップボード一時置き場アプリを自作する。既存アプリは各OS単体対応かつ有料のものが多く、無料でWindows/Mac両対応の選択肢が乏しいことが動機。

### 1.3 目的
- ドラッグ&ドロップ操作を快適にする画面端常駐の「一時置き場（シェルフ）」を提供する
- クリップボード履歴の記録・ピン留め・検索を提供する
- Windows / macOS の両方で同一の操作感を実現する

### 1.4 対象ユーザー
開発者本人（shiki）の個人利用を第一とする。将来的なOSS公開は視野に入れるが、要件定義段階では個人ユースケースを優先する。

---

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| シェルフ (Shelf) | 画面端に表示される、ファイル/フォルダ/テキストの一時置き場ウィンドウ |
| ピン留め | クリップボード履歴やシェルフ内アイテムを自動削除対象から除外する操作 |
| スタック | 複数のクリップボードアイテムを1つにまとめる操作 |
| ドロップターゲット | OSのドラッグ&ドロップ操作を受け付けるウィンドウ/領域 |

---

## 3. 機能要件

優先度は P0（必須・MVP）/ P1（早期に欲しい）/ P2（あれば良い）の3段階。

### 3.1 コア機能：シェルフ

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-01 | シェルフ表示/非表示 | ホットキーでシェルフウィンドウの表示・非表示を切り替える | P0 |
| F-02 | ファイルドロップ格納 | ファイル/フォルダをシェルフにドラッグ&ドロップして一時格納する | P0 |
| F-03 | シェルフからの再ドロップ | シェルフ内アイテムを任意のアプリ/フォルダへドラッグ&ドロップで送り出す | P0 |
| F-04 | 複数アイテム格納 | シェルフ内に複数ファイルを保持し、個別・一括で操作可能にする | P0 |
| F-05 | アイテム削除 | シェルフ内アイテムを個別または一括で削除する | P0 |
| F-06 | ロック機能 | 特定アイテムを「全消去」の対象から除外する | P1 |
| F-07 | プレビュー表示 | アイテムにカーソルを合わせる、またはショートカットでプレビュー表示する | P1 |
| F-08 | ドラッグ開始時の自動表示 | OS全体でのドラッグ操作開始を検知し、シェルフを自動表示する | P2（OS依存の実装難度が高いため後回し） |
| F-09 | よく使うフォルダ登録 | 任意のフォルダをショートカットとしてシェルフ内に常時表示する | P2 |
| F-10 | 表示位置/透明度設定 | シェルフの表示位置（画面端の上下左右）と透明度を設定できる | P1 |

### 3.2 クリップボード機能

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-11 | クリップボード履歴記録 | テキスト/画像/ファイルパスのコピー履歴を自動記録する | P0 |
| F-12 | 履歴からの貼り付け | 履歴一覧からアイテムを選択してクリップボードに戻す、またはアクティブなアプリへ直接貼り付ける | P0 |
| F-13 | ピン留め | 特定の履歴アイテムを自動削除対象から除外する | P1 |
| F-14 | 検索 | 履歴内をテキスト検索する | P1 |
| F-15 | スタック/マージ | 複数のクリップボードアイテムを結合して1つのテキストにする | P2 |
| F-16 | 自動クリア | 一定件数/期間を超えた履歴を自動削除する（設定可能） | P1 |
| F-17 | カテゴリ/タグ分類 | 履歴アイテムにタグを付与し、フィルタ表示する | P2 |

### 3.3 周辺機能

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-18 | メニューバー/システムトレイ常駐 | 常駐アイコンからシェルフの表示切り替え・設定画面を呼び出す | P0 |
| F-19 | ログイン時自動起動 | OS起動時にアプリを自動起動する | P1 |
| F-20 | グローバルホットキー設定 | シェルフ呼び出し・クリップボード履歴呼び出しのショートカットをカスタマイズできる | P0 |
| F-21 | 右クリックメニュー | シェルフ内アイテムに対する共有/圧縮/パスコピー等のコンテキストメニュー | P2 |
| F-22 | デバイス間同期 | 複数端末間でシェルフ/クリップボード内容を同期する | P2（Out of scope寄り、将来検討） |

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 対応OS | Windows 10/11、macOS（Apple Silicon優先、Intel対応は可能な範囲） |
| パフォーマンス | 常駐時のメモリ使用量を抑える（Electron比で軽量なランタイムを採用） |
| 起動速度 | シェルフ呼び出しからウィンドウ表示までの体感遅延を最小化する |
| データ永続化 | アプリ再起動後もシェルフ内容/クリップボード履歴を保持する |
| プライバシー | クリップボード履歴はローカル保存を基本とし、外部送信は行わない（F-22実装時を除く） |
| ライセンス | 無料・可能であればOSS化を前提とする |

## 5. システム構成／技術スタック

| 層 | 採用技術 | 備考 |
|---|---|---|
| フロントエンド | Svelte 5 + TypeScript | シェルフUI、クリップボード履歴UI、設定画面 |
| バックエンド | Rust（Tauri） | クリップボード監視、ドラッグ&ドロップ処理、ホットキー管理 |
| データ永続化 | SQLite（rusqlite） | クリップボード履歴、ピン、タグを管理。ファイル自体は参照のみで実体コピーは行わない |
| クリップボード抽象化 | arboard または clipboard-rs | Windows/macOS差異の吸収 |
| Windowsドラッグ&ドロップ | windows-rs（COM / IDropTarget） | OLEベースの実装 |
| macOSドラッグ&ドロップ | NSPasteboard / NSDraggingSession（Tauri経由のネイティブ連携） | 自動検知（F-08）は別途調査が必要 |
| グローバルホットキー | tauri-plugin-global-shortcut | |

## 6. 画面要件（概要）

- **シェルフウィンドウ**: 画面端常駐、半透明、ドラッグ&ドロップ対応領域
- **クリップボード履歴パネル**: 一覧表示、検索バー、ピン留めアイコン
- **設定画面**: ホットキー設定、表示位置/透明度、自動クリア期間、自動起動ON/OFF
- **システムトレイ/メニューバーアイコン**: 左クリックでシェルフ表示切り替え、右クリックで設定/終了メニュー

| フェーズ | 内容 | 含む機能ID |

## 8. 制約事項・リスク

- macOSにおけるグローバルなドラッグ開始検知（F-08）は、Accessibility APIまたはprivate APIへの依存が想定され、実装難度・審査（Mac App Store配布時）への影響が高い。App Store外配布（notarization経由の直接配布）を前提とする
- クリップボード監視はmacOS側でプッシュ通知APIが存在しないため、ポーリング方式（数百ms間隔）を採用する。バッテリー消費への影響を検証する必要がある
- Windowsのセキュリティソフトによっては、クリップボード監視やグローバルフックが誤検知される可能性があるため、コード署名を検討する

## 9. Out of Scope（本要件定義の対象外）

- クラウド経由の複数ユーザー間ファイル共有（Edge Drop本家の「自分宛メモ」的機能を超えた共同編集等）
- モバイル（iOS/Android）対応
- Linux対応（将来検討の余地はあるが本要件定義では扱わない）
